# Foundry M0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the `foundry` Claude Code plugin: the two entry commands, the orchestrator, and all eight heroes, runnable end to end on a scratch repo.

**Architecture:** A Claude Code plugin made of Markdown prompt files. The two interactive heroes (Anaximander, Hypatia) are **skills** so they run in the owner's main session and can talk to the owner; the six unattended heroes are **subagents** dispatched by the `factory` skill. All cross-file names (statuses, labels, verdicts, paths) are defined once in `skills/factory/contract.md` and pinned by tests.

**Tech Stack:** Claude Code plugin format (`.claude-plugin/plugin.json`, `skills/`, `agents/`), `gh` CLI, Python 3.9 stdlib `unittest` for structural tests, `claude plugin validate`.

**Spec:** `docs/superpowers/specs/2026-11-23-foundry-workflows-design.md`

## Global Constraints

- Plugin name: `foundry`. Entry points: `/foundry:wise-counsel`, `/foundry:start-milestone [milestone]`.
- Milestone statuses, exactly: `planned`, `in-progress`, `shipped`.
- Flags, exactly: `security`, `ui` (values `yes` / `no`).
- PR labels, exactly: `foundry:building`, `foundry:review-r1`, `foundry:review-r2`, `foundry:review-r3`, `foundry:awaiting-homer`, `foundry:escalated`, `foundry:ready-to-merge`.
- Reviewer verdicts: `PASS`, `CHANGES`. Finding tags: `blocking`, `nit`. Homer verdicts: `APPROVE`, `ESCALATE`.
- Paths in target repos: `docs/roadmap.md`, `docs/milestones/NN-<slug>.md`, `docs/specs/<date>-<milestone-slug>.md`, `docs/builds/<date>-<milestone-slug>.md`.
- Models: builder `opus`, reviewer-code `sonnet` (orchestrator overrides to `opus` for large/core/flagged PRs; never `haiku`), reviewer-security `opus`, reviewer-ux `sonnet`, reviewer-ui `haiku`, approver `opus`. Anaximander and Hypatia run on the session model and should be used with Opus.
- Review cap: 3 rounds. One milestone `in-progress` at a time.
- C3: no stage relies on session memory; every stage reads files + PR state.
- C6: nothing is written to `main` except through a PR the owner merges.
- The factory never merges a PR.

## Review Focus

1. **`start-milestone` while another milestone is `in-progress`** — refuses and offers resume / abandon; never starts a second build. (Task 5)
2. **Hand-written milestone missing a field** (no acceptance criteria, no flags) — Hypatia lists the missing fields and stops; she does not invent them. (Task 5)
3. **Target repo with no CI or no test runner** — spec gets a CI task; the readiness gate falls back to local checks and `build.md` says so. (Tasks 5, 6)
4. **Session closed mid-run** — re-running `start-milestone` reads the PR label and resumes at that stage, not from the start. (Task 9)
5. **`gh` unauthenticated or no GitHub remote** — orchestrator stops before any agent runs and tells the owner how to fix it. (Task 9)

## File Structure

```
.claude-plugin/plugin.json        manifest
skills/
  wise-counsel/SKILL.md           Anaximander (interactive, main session)
  start-milestone/SKILL.md        Hypatia (interactive) → hands to factory
  factory/SKILL.md                orchestrator for the unattended stretch
  factory/contract.md             the single list of shared names + file formats
  factory/templates/
    roadmap.md  milestone.md  spec.md  build.md
agents/
  builder.md  reviewer-code.md  reviewer-security.md
  reviewer-ux.md  reviewer-ui.md  approver.md
tests/
  contract.py                     shared constants mirrored from Global Constraints
  test_plugin.py                  manifest + frontmatter
  test_contract.py                templates + contract.md
  test_skills.py                  skill content checks
  test_agents.py                  agent content checks
docs/superpowers/notes/
  2026-11-23-subagent-escalation.md   Task 2 findings
```

Content tests check **contract tokens and required section headings**, not prose. Every agent file has the headings `## Inputs`, `## Outputs`, `## Rules`, `## Escalation`. Every hero skill has `## Inputs`, `## Outputs`, `## Rules`, `## Handoff`.

Run all tests with: `python3 -m unittest discover -s tests -v`
